# RT-0033 계산 결과 — 판정단 가중치 결탁 포획 비용

**재현:** `python3 exp3/rt0033_veteran_capture.py` (정확 분수 계산, 순열 완전열거 — 몬테카를로 아님)

## 재해석 — 원래 우려("블록해시 그라인딩")보다 싼 공격이 있었다

기존 docstring의 "제안자 편향"은 블록 생성자(검증자) 권한을 전제로 했다. 코드를 다시 보니
**검증자 권한이 전혀 필요 없는 더 싼 경로**가 있다: `openCase`는 누구나 `judgeFee`만 내면
호출 가능하고, 서로 다른 `requestHash`마다 시드가 자연히 독립적이다. 결탁 판정자 집단은
그냥 여러 사건을 열어보고(judgeFee만 내고) **우연히 전원 자기편이 뽑힌 사건만 골라 쓰면 된다**
— "사건 쇼핑". 그라인딩(블록 조작) 불필요, 자본만 있으면 아무나 시도 가능.

## 결론

**포획 확률은 풀 크기와 결탁 지분에 극도로 민감하다.** 풀이 작고(≤15명) 결탁이 veteran의
큰 지분(≥30%)을 차지할 때만 공격이 "싸진다"(수백 judgeFee 이내). 풀이 30명만 넘어가도
비용이 수천~수만 judgeFee로 뛰어 사실상 대부분의 청구 가치를 넘어선다.

**권고 (코드 수정 아님 — 배포 규칙):**
1. **최소 풀 크기 하한** — 이 판정 메커니즘은 판정자 풀이 일정 규모(예: ≥30명, 결탁 시나리오
   비용이 수천 judgeFee를 넘는 지점) 미만인 동안은 "안전하다"고 표시하지 않는다. Exp30 이
   W(챌린지 창)에 대해 만든 "W ≥ k·지연" 하한 규칙과 같은 종류의 배포 전제 규칙이 필요하다.
2. **VETERAN_WEIGHT 재검토** — 5배는 소수 결탁의 지분 집중을 지수적으로 키운다. 더 낮은
   가중치(예: 2~3배)나 지분 상한(한 클러스터가 가질 수 있는 최대 가중치 비율)을 z3 로
   재계산해 트레이드오프(신참 스팸 방지 vs 결탁 저항)를 다시 볼 가치가 있다.
3. 블록해시 그라인딩(원래 우려)은 이 "사건 쇼핑" 경로보다 비싸고 더 어려우므로 후순위 —
   VRF 도입 논의는 지분 집중 문제가 더 급함을 확인한 뒤로 미뤄도 된다.

**정직한 한계:** 이 계산은 판정자가 정확히 온체인 지분 그대로 "결탁 클러스터"로 식별
가능하다고 가정(같은 신원인지, 얼마나 흩어져 등록했는지는 온체인에서 직접 안 보임 — 실측
불가, 설계 논의의 재료일 뿐). 방어벽으로서의 최소 풀 크기 숫자는 이 계산의 근사치이지
프로토콜에 하드코딩된 값이 아니다.
