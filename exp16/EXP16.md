# Exp16 — 바인딩 회로: 증명을 특정 입력·모델·출력에 묶는다 (proofHash 미결 해소)

> 2026-08-27 · Exp14 회로는 입력이 private — 증명이 "어떤 문장에 대한 것인지"
> 온체인에서 알 수 없어 재사용 공격이 가능했다(설계서 미결 1번). 이번에:
> 입력 poseidon 해시=공개 인스턴스, 모델 가중치=회로 박제(vk가 곧 모델 커밋),
> 출력=공개. 증명 하나가 (입력, 모델, 출력) 삼중을 묶는다.

## 사전 등록 킬 기준 (실행 전 박제)

- **K1 (바인딩 성립)**: hashed/public 입력으로 파이프라인 완주 + 온체인
  verify=true + 공개 인스턴스에 입력 해시·출력이 실제로 나타나야 한다.
- **K2 (재사용 불가)**: 인스턴스(입력 해시 또는 출력)를 1워드라도 변조한
  calldata는 온체인 검증에 실패해야 한다. 실패하지 않으면 바인딩 무효 → 기각.
- **K3 (비용 델타)**: Exp15 대비 가스·회로 크기·증명 시간 변화 보고. 가스가
  3,000만 초과 시 "온체인 직접 검증 불가" 판정.

## 정직성 라벨

- 입력 해시는 poseidon(필드 인코딩된 ids) — requestHash(keccak, 문제 원문)와의
  대응은 오프체인 매핑 계층 몫임을 명기 (완전한 종단 바인딩은 후속).
- 모델 커밋 = vk 동일성. 모델 버전업 시 vk 교체 거버넌스는 설계서 미결 유지.

## 결과 (2026-08-27) — K1·K2·K3 통과

| 항목 | 실측 (괄호: Exp15 비바인딩 대비) |
|---|---|
| 공개 인스턴스 | 63개 = 입력 poseidon 해시 1 + 출력 로짓 62 |
| 온체인 검증 | 성공 — **verify 가스 975,182** (+110,530) |
| 배포 코드 | **24,257B — EIP-170까지 여유 319B** (경계 근접 명기) |
| 증명 생성 | 21.4초 (+4.2) · 검증 0.2초 · logrows 18 동일 |
| K2 변조 시험 | 입력 해시 교체 → **암호학적 기각**(constraint 불일치, 로컬·온체인 모두). 출력 교체 → 기각(단, 인코딩 파손 단계 기각 — 필드 유효 변조의 암호학적 기각은 입력 해시 건으로 입증됨) |

부수 관찰: calldata 꼬리 패딩 바이트는 검증자가 무시한다(1차 시험이 무딘
이유) — 인스턴스·증명 본문 밖 바이트라 보안 무관, 기록만 남김.

**의미:** 증명 하나가 (입력 해시, 모델=vk, 출력) 삼중을 묶는다 — "다른 문장에
대한 증명"이라는 재사용 주장이 수학적으로 불가능해짐. proofhash-design.md
미결 1번 해소. 남은 미결: poseidon(ids)↔requestHash(keccak) 오프체인 매핑
계층, vk 교체 거버넌스, 코드 크기 여유 319B(회로 변경 시 EIP-170 초과 위험).
