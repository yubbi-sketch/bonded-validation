> 설계서: docs/8004-bonded-validation-설계서-v1.md · 컨트랙트: exp3/contracts/src/

## 착수 게이트 (갭 재확인 — G1 방식)

공식 erc-8004-contracts는 레지스트리만 제공(슬래싱은 스펙 명시로 범위 밖).
세간의 "에이전트 스테이킹"은 오라클·GPU노드·검증자 담보 계열.
**[발화 단위 발화자 담보 + 8004 검증 레지스트리 + 결정론 검증기 + 기권 무손실]
조합의 선점자 미확인 → 착수.** (갭 주장은 갱신 가능 — 사서석 지속 추적)

## 만든 것

1. **Erc8004Registries.sol** — 스펙 시그니처 그대로의 Identity·Validation 레지스트리
   최소 구현 (단순화 명기: ERC-721 상속·metadata·getSummary 필터 생략, Draft 대비 어댑터 취급)
2. **BondedValidator.sol** — BondManager(Exp3) 후계:
   - 8004 agentId 지갑 검증 → 신원 없는 발화 불가
   - 자유 담보 없으면 `validationRequest` 자체 불성립 → 담보 없는 발화 불가
   - 판정 점수(0~100)가 레지스트리에 기록 → 평판 원료
   - **tag "abstain" = 점수 무관 담보 무손실** (Exp2 실증 규칙의 온체인 실장)
3. Forge 테스트 **8/8 통과** (무담보·비지갑 발화 거부 / 슬래시·해제·기권 / 레지스트리
   평균 / 도망 방지)

## 라이브 시연 (Anvil, 담보 발화 300건, 추출기는 Exp2 기권 τ=0.9 장착)

| 에이전트 | 행동 (100문제) | 담보 | 온체인 평판(avg) |
|---|---|---|---|
| honest | 정답 100 | 50 → **50** | **100** |
| **extractor+verifier+abstain (우리)** | 정답 84 · 오답 0 · 기권 16 | 50 → **50 (무손실)** | 84 |
| hallucinator | 정답 50 · 오답 50 | 50 → **0 (파산)** | 50 |

**서사 완성:** Exp3(기권 없음)에서 추출기는 1 잃었다 → Exp5(기권 장착)에서 **0 잃었다.**
"모르면 모른다"가 온체인 경제로 번역됐고, 근거 없는 발화는 100문제 만에 전 재산을
잃었다. 지붕 명제 3요소가 처음으로 한 체인 위에서 동시 작동:
서명(8004 신원·지갑 검증) · 담보(BondedValidator) · 증명(검증기 판정→레지스트리).

## 정직성 한계

1. judge는 여전히 신뢰 오라클 (탈중앙 판정 = 후속 연구 본류)
2. ERC-8004는 Draft/Review — 인터페이스 변동 리스크, 어댑터로 격리
3. **평판 설계 미결**: 기권을 0점으로 집계해 평균(84)을 끌어내림. 스펙의 tag 필터
   getSummary를 쓰면 기권 분리 가능 — "기권은 평판에 중립이어야 하는가"는 Exp6 질문
4. 첫 실행에서 측정 레이스 발견(채굴 전 eth_call 읽기 → 93/100 오집계) — flush 도입으로
   수리. 교훈: 온체인 실측은 채굴 확정 후 읽는다.
