# 책임 공개 절차 (Responsible Disclosure)

> 2026-08-30 오너 도장 확정 (세종 결재 AP-20260829234213-8694F4, 승인 09:45:19).
> 우리 검사기·증명이 제3자 프로토콜에서 취약점(반례)을 발견했을 때 따르는 규칙. 변경은 결재로만.

## 원칙
신뢰를 파는 우리가 무책임 공개로 남을 위험에 빠뜨리면 안 된다. 발견은 무기가 아니라 책임이다.

## 절차
1. **비공개 통지** — 발견 즉시, 해당 팀의 보안 연락처(security.txt · Immunefi · 공식 채널)로 조용히 알린다. 재현 명령·성질·경계를 함께.
2. **대기** — 기본 **14일**. 팀이 더 요청하면 합리적 범위에서 연장. 활발히 수정 중이면 배포까지 대기.
3. **공개** — 수정 완료 후, 또는 무응답·기한 경과 시에만. 공개물에는 팀의 대응(수정/무응답)을 사실대로 기재.
4. **긴급 예외** — 이미 악용 중이거나 자금이 실시간 위험이면, 통지와 동시에 완화책을 우선. (판단은 오너 도장)

## 하지 않는 것
- 통지 없는 선(先)공개 금지.
- 공개를 협상 카드(유료 전환 압박)로 쓰지 않는다 — 매수 유인 제거 원칙과 동형.
- 재현 불가·경계 밖 사건을 "취약점"으로 공표하지 않는다(증거 규율).

## 우리 증명서와의 연결
담보 감사 증명서의 '거짓(반례)' 판정이 제3자 컨트랙트에 대한 것일 때, 증명서 공개는 이 절차를 통과한 뒤에만.
