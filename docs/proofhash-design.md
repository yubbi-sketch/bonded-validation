# proofHash 통합 설계 — 증명 실린 평결 (v0.4 후보, 구현 전 심의 필수)

> 2026-08-27 · Exp14(증명 17.2s/0.1s)·Exp15(온체인 검증자 가스 실측)의 다음 층.
> **상태: 설계 초안 — 슬래싱 규칙 변경이므로 A2A 심의 + 오너 결재 전 구현 금지**
> (기준: "큰 작업은 심의 먼저", 분쟁해소 v0.1 때와 동일 절차)

## 목표

확대재판의 마지막 신뢰 가정 — "5인 중 3인 정직" — 을 결정론 범주에서
수학으로 교체한다. 판정 표(vote)에 zk 증명을 첨부할 수 있게 하고, 검증된
증명이 있는 표는 다수결보다 우선한다.

## 설계 스케치

1. **proofHash 자리**: `voteVerdict`의 기존 `evidenceHash`를
   `keccak(zk-proof)`로 쓰는 관례를 규범화(MUST if available). 스토리지 변경 0.
2. **ZkVerdictGate**: Halo2Verifier(Exp15) 주소를 아는 얇은 컨트랙트.
   `attest(requestHash, proofCalldata)` — 온체인 검증 통과 시
   `proven[requestHash][judge] = true` 기록. 증명의 public input에
   requestHash·모델 커밋(가중치 해시)·출력이 묶여야 함(재사용 공격 방지).
3. **규칙 변경 (심의 대상)**:
   - R1 증명된 표는 소수파여도 몰수 면제 (수학이 맞다는데 돈을 뺏을 수 없다)
   - R2 증명된 표가 존재하면 그 평결이 다수결을 **덮는다** (결정론 범주 한정)
   - R3 증명된 표와 상충하는 모든 표는 소수파로 간주 → 기존 몰수 규칙 적용
4. **경제 재설계 질문 (심의에서 다룰 것)**:
   - R2가 서면 "패널이 왜 필요한가?" → 증명 생성 비용(17s+가스)을 안 내는
     게으른 경로가 기본, 분쟁 시에만 증명 — 낙관적 구조 유지
   - 가짜 모델 커밋 공격: 증명은 "모델 M을 돌렸다"만 보장 — M이 합의된
     추출기인지는 모델 커밋 해시가 등록부와 일치해야 함
   - Exp15 가스가 크면: L2 전제 또는 분쟁시에만 온체인 검증(낙관적 zk)

## 미결

- public input 바인딩 형식(현 Exp14 회로는 ids가 private input — requestHash
  바인딩하려면 입력을 public instance로 승격 재컴파일 필요: 후속 실험)
- 집계 증명(여러 판정 1증명), 검증자 업그레이드 거버넌스(모델 버전업 시)
